# 0013: Read ADIF's ADX XML form as records

Decided 2026-11-08 for qso-graph-desktop#172, Gate C.

## What was decided

[ADIF 3.1.7, section IV.B](https://adif.org.uk/317/ADIF_317.htm#ADX_File_Format) defines ADX;
ADIF is the source of truth. `records::parse` chooses ADX when the first non-whitespace bytes after
an optional UTF-8 BOM start `<?xml` or `<ADX`; all other input is read as ADI. An input that claims
ADX and fails is refused, never retried as ADI. File names do not choose the format.

Element and attribute names are uppercase as ADIF requires. The accepted ordinary QSO field names
are ADIF 3.1.7 section III.C names; a record child outside those names and the `APP`/`USERDEF` forms
is refused. This is ADIF syntax validation, not a LoTW station-location table. A header is discarded
as in ADI; ADX requires both `HEADER` and `RECORDS`.
An `APP` QSO field becomes `APP_PROGRAMID_FIELDNAME`, with its type, and a `USERDEF` QSO field
becomes the field named by `FIELDNAME`, with its record type ignored. The ADI reader keeps unknown,
application-defined, and user-defined fields in order; QSO conversion uses the fields it needs.
Decoded values are held in wiping buffers, as for ADI. XML line-end normalization applies to ADX.

The XML reader bounds elements, depth, attributes, decoded values and named `RECORD` elements;
ADX also refuses more than 256 fields in a record or 2,000,200 fields in all. Its existing
2,000,000-element XML ceiling can refuse a document sooner because record and container elements
also count. Processing instructions are ignored only for ADX, have a 64 KiB limit and count as
elements; an `xml` target is refused. Existing XML formats retain their strict reader.
DTD declarations, unknown entities, malformed XML, unexpected structure, and text outside fields
are refused. XML's five named entities and numeric character references are accepted.

Namespace declarations are ignored, but prefixed element names are refused. QG Trust is stricter
than ADIF in two places: it refuses CDATA everywhere (ADX containers hold elements and ADIF forbids
CDATA in fields), and refuses non-ASCII namespace prefixes (the shared XML reader accepts ASCII
names). These restrictions keep the existing bounded XML reader and its other callers unchanged.

## TQSL comparison

`tqsl_beginADIF` attempts XML first and falls back to ADI when XML parsing fails. QG Trust selects by
content and refuses a malformed ADX claim rather than retrying, so an invalid XML file cannot be
silently interpreted as a different log. tqsllib does not require `HEADER`; ADIF specifies it and
QG Trust requires it. tqsllib reads ADX record children by their element names;
it does not map the attributes of `APP` and `USERDEF` into ADI field names. QG Trust maps them as
ADIF defines them and retains the corresponding fields as its ADI reader does. QG Trust also applies
its own bounds, strict XML subset and errors. Neither parser's error behavior is a signing format.

## Evidence

Synthetic equivalent ADI and ADX logs produce byte-identical `.tq8` files with the test PKI and a
fixed time. The published ADIF 3.1.7 test files are fetched in Linux CI with their archive SHA-256
verified; they are not redistributed here because their terms are unclear. Local tests use
`QGT_ADIF_TEST_DIR` and state when it is unset. The paired files contain international forms in ADX,
and are compared with those differences identified. Tests plant malformed input, excessive sizes,
processing instructions, namespace names and each disallowed XML construct.
